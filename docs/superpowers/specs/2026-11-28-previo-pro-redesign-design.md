# PREVIO 전문 소프트웨어 리디자인: 설계 (2026-11-28)

- 요청 원문: `2026-11-28-previo-pro-redesign-request.md`
- 현황 분석: `2026-11-28-previo-pro-redesign-analysis.md`
- 이 문서는 원문 이후 대화에서 사용자가 정한 것과, 진행자(Claude)가 맡아서 정한 것을 합친 설계다.
  - 진행자가 정한 것은 **[판단]**으로 표시한다.
  - 사용자가 정한 것은 **[사용자]**로 표시한다.

## 1. 의도

PREVIO가 "AI가 만든 웹앱"처럼 보이지 않고 실제로 쓰는 제작 도구처럼 보이고 움직이게 한다.
컴퓨터는 Cinema 4D식 작업 구조, 조작은 Apple식으로 쉽게, 도구는 촬영감독이 쓰는 만큼만 간결하게 한다. **[사용자]**

사용자는 두 부류다. **[사용자]**
- **간편 모드**: 촬영을 잘 모르지만 AI 영상을 만드는 사람. 클릭 몇 번으로 구도를 짜고, AI에 넣을 프롬프트를 얻는 것이 목적이다.
- **프로 모드**: 실제 촬영 때 어떻게 찍을지 기획하는 사람(감독·촬영감독·조감독). 렌즈·초점·노출·조명·장비를 정확히 다룬다.

## 2. 목표

1. 컴퓨터: 고정 작업 공간
   - 위 툴바, 왼쪽 도구 팔레트, 가운데 뷰포트, 오른쪽 속성 인스펙터, 아래 타임라인
   - 패널은 폭과 높이를 조절하고 접을 수 있다. 자유 이동과 도킹은 없다.
2. 뷰포트: 한 화면 / 세 화면. 세 화면은 3D(왼쪽, 가장 큼) · 탑(오른쪽 위) · 카메라(오른쪽 아래) **[사용자]**
   - 모든 칸이 같은 장면을 공유한다.
   - 어느 칸에서든 물체를 고르고 옮길 수 있다.
3. ⌘K / Ctrl+K 도구 검색(커맨더)
4. 휴대폰: 컴퓨터와 다른 배치. 화면 하나, 아래 탭, 설정 시트
5. 스토리보드 작업 칸: 세로 목록 **[사용자]**
   - 샷마다 그림, 쓸 수 있는 글, 샷 크기·앵글·렌즈 같은 정보, AI 프롬프트가 한 줄에 놓인다.
   - 샷을 누르면 바로 3D 편집으로 간다.
6. 홈 화면: 프로젝트 관리 중심으로 간결하게
7. 디자인 시스템: 무광 검정 + 라임 녹색(카메라·렌즈 콘셉트) **[사용자, 원문의 차콜·블루 퍼플을 대체]**
8. 간편 모드 세 가지 **[사용자]**
   - AI 프롬프트 기본값을 "실사"가 아닌 "기본"으로 바꾼다.
   - 클릭 한 번으로 샷 크기·앵글을 맞춘다.
   - 사진으로 자동 구도를 잡는다.

## 5. 제약

- 앱은 `index.html` 한 파일의 바닐라 JS와 three.js(r160)다. 부품은 `ui/`의 Astryx 연결 장치가 그린다. 이 구조를 유지한다.
  - 기존 요소의 id·class·data 속성은 지우거나 이름을 바꾸지 않는다(CLAUDE.md).
- 저장 형식 `SCHEMA = 10`을 유지한다. 새 데이터가 필요하면 선택 필드로 더해서, 예전 프로젝트가 그대로 열리게 한다.
- 화면 글은 모두 한국어(CLAUDE.md).
- 휴대폰은 가로가 기본이다(기존 결정). 다만 스토리보드는 세로로 쓴다 **[사용자]**.
- 이미 정한 조작은 유지한다(`decisions.md`):
  - 화각·조리개처럼 정해진 숫자는 눈금자, 0~100 값은 돌리는 다이얼
  - 녹화 빨간 테두리는 전체 재생 중에만
  - 판독값 15px, 글자 최소 12px
  - Esc로 패널 닫기, F6으로 영역 이동

## 6. 만드는 방법: 고려한 것과 고른 것

| 결정 | 고려한 방법 | 고른 것과 이유 |
|---|---|---|
| 칸마다 조작 | ① 모든 칸에서 고르고 옮기기 ② 큰 칸만 조작, 작은 칸은 보기 전용 | **①**. 원문이 "한 뷰포트에서 옮기면 다른 뷰포트에 반영"을 요구한다. 전역(`viewer`, `worldV`, `worldHandles`, `gizmoSpot`, `wsz`, `mode`)을 칸 객체로 묶고, 그리고 입력받을 때 그 칸의 값으로 잠깐 바꿔 끼운다(`drawWorld2`에서 쓴 방식을 넓힌다). **[판단, 사용자 승인]** |
| 사진 속 사람 찾기 | ① 기기 안 인식 모델(MediaPipe 자세 인식) ② 사람이 머리·발을 눌러 표시 ③ 클라우드 AI | **① + ②**. 모델은 저장소에 두고 처음 쓸 때만 받는다. 오프라인 캐시가 되고 사진을 밖으로 보내지 않는다. 사람을 못 찾으면 ②로 넘어간다. **[판단, 사용자 승인]** |
| 화면 틀 공사 | ① 지금 HTML/CSS 틀을 고쳐 옮기기 ② Astryx 레이아웃 부품으로 React 틀을 새로 짜기 | **①**. 기존 코드가 요소 위치와 id에 기대는 곳이 많아 ②는 위험하다. **[판단, 사용자 승인]** |

## 7. 화면 설계

### 7-1. 컴퓨터 작업 공간

화면 폭이 1000px 이상이고 높이가 560px 이상이면 컴퓨터 배치다. 그보다 작으면 휴대폰 배치를 쓴다. 태블릿도 이 기준을 따른다(12절 4 참고). **[판단]**

```
┌ 위 툴바 ───────────────────────────────────────────────────────────┐
│ PREVIO  씬 이름 ● 저장됨   ↶ ↷   [⌘K 검색]   [한 화면|세 화면]  내보내기 │
├──┬──────────────────────────────────────────────┬──────────────────┤
│도│                                              │ 속성 인스펙터       │
│구│   뷰포트 (한 화면 또는 세 화면)                   │ (고른 대상에 따라)   │
│팔│                                              │                  │
│레│                                              │                  │
│트│                                              │                  │
├──┴──────────────────────────────────────────────┴──────────────────┤
│ 타임라인 · 샷 띠 (접기 가능, 높이 조절)          [편집 | 스토리보드]       │
└────────────────────────────────────────────────────────────────────┘
```

**위 툴바** **[판단]**
- 올리는 것: 프로젝트명(바로 고치기), 저장 상태, 되돌리기·다시, 검색(⌘K), 뷰포트 배치(한 화면/세 화면), 내보내기
- 편집↔스토리보드 전환: 타임라인 머리로 옮긴다(작업 칸 전환이라 아래가 자연스럽다)
- 간편/프로 전환, 튜토리얼, 포커스 연습, 조작 가이드: 로고 메뉴와 검색으로 옮긴다
- 마우스를 올리면 이름과 단축키를 보여 준다

**왼쪽 도구 팔레트**: 세로 줄, 아이콘 + 이름. 그룹마다 접고 펼친다. 있는 기능만 넣는다. **[판단]**

| 그룹 | 도구 (기존 기능) |
|---|---|
| 즐겨찾기 | 사용자가 고른 도구. 도구를 길게 누르거나 오른쪽 클릭 → "즐겨찾기에 추가". 비어 있으면 그룹을 숨긴다 |
| 선택·이동 | 선택(다른 도구 모드를 끄고 고르기로 돌아감), 카메라 이동 방식 끌기/축(J), 물체 옮기기 |
| 회전 | 물체 90° 회전(왼쪽·오른쪽), 수평 맞추기(O) |
| 카메라 | A·B 바라보기(U), 맞춤(0), 렌즈 넓게/좁게(Z/X), 크레인(장비가 지미집일 때) |
| 조명 | 조명 추가, 조도 히트맵, 시간·날씨 |
| 세트 | 인물 추가, 가구 추가, 짓기(벽·바닥·블록) |
| 오브젝트 | 복제, 삭제(고른 것이 있을 때만 켜짐) |
| 측정 | 줄자(탑 칸), 그리드 표시 |
| 주석 | 가상선(180° 선), 동선(인물 동선만) |

- 원문의 "스케일"은 넣지 않는다. 일반 크기 조절 기능이 없고, 지은 벽의 길이·높이·두께는 인스펙터 값으로 둔다. **[판단, 원문: 없는 도구는 만들지 말 것]**
- 팔레트는 아이콘만 보이게 좁힐 수 있다(폭 52px ↔ 168px).

**가운데 뷰포트**: 7-2 참고.

**오른쪽 속성 인스펙터**: 고른 대상에 따라 바뀐다. 폭을 끌어서 조절하고(기존 `.dresize`) 접을 수 있다. **[판단]**

| 고른 것 | 섹션 (기존 속성만) |
|---|---|
| 카메라(아무것도 안 골랐을 때 기본) | 렌즈 · 초점 · 노출 · 거리 · 센서 · 장비(프로). 간편 모드는 맨 위에 "샷 크기 · 앵글" 버튼과 "사진으로 구도" |
| 조명 | 광원 종류(기구·앞에 다는 것) · 밝기(다이얼) · 색온도/젤 · 위치(높이 포함) · 방향(팬·틸트, 스팟↔플러드) |
| 인물 | 배역·성별·나이·키, 위치, 바라보는 방향, 자세 |
| 가구·지은 것 | 위치, 회전, 크기(지은 벽의 길이·높이·두께처럼 있는 경우만), 재질 등 기존 세부 설정 |

- 섹션 모양: 제목 한 줄과 값 줄. 섹션은 접을 수 있다. 카드나 상자 안에 상자를 넣지 않는다.
- 씬 전체 설정(조명의 시간·날씨, 공간)은 아무것도 고르지 않았을 때 카메라 아래 "씬" 섹션으로 둔다.

**아래 타임라인**: 샷 띠와 타임라인을 하나로 합친다. 샷 길이에 비례한 칸이고 재생 머리가 있다. **[판단]**
- 기능: 순서 끌기, 새 샷·복제·삭제, 이 샷 재생·전체 재생, 시간(초)
- 고른 샷의 샷 설정은 타임라인 머리에 둔다: 무빙, 길이, 메모. 가상선·테크비즈·촬영 순서는 펼침 메뉴
- 접기(기존 `stripFold`)와 높이 조절을 둔다
- 머리 오른쪽에 편집 / 스토리보드 전환이 있다

### 7-2. 뷰포트

- **배치**: 한 화면 / 세 화면을 툴바에서 고르고, 고른 배치는 기억한다. **[사용자]**
  - 기본값: 화면 폭 1280px 이상이면 세 화면, 아니면 한 화면 **[판단]**
- **세 화면**: 왼쪽 3D(가장 큼) · 오른쪽 위 탑 · 오른쪽 아래 카메라. 경계선을 끌어 크기를 조절한다. **[사용자]**
- **칸마다**:
  - 위쪽에 얇은 머리줄이 있고, 시점 메뉴(3D/탑/카메라)와 표시 옵션(그리드, 구도 가이드, 폴스컬러 등 그 시점에 있는 것)을 둔다.
  - 더블클릭하면 그 칸이 최대화되고, 다시 더블클릭하면 원래대로 돌아온다.
  - 마지막으로 누른 칸이 활성 칸이 되고, 테두리 1px 라임으로 표시한다.
- **시점은 칸마다 따로**: 3D 칸끼리도 각자 시점을 가진다. 배치를 바꾸거나 최대화했다 돌아와도 각 칸의 시점을 유지한다.
- **같은 장면**: 렌더러 하나와 장면 하나를 그대로 쓴다. 한 칸에서 옮기면 다른 칸도 다음 그리기에 반영된다.
  - 활성 칸은 즉시 그리고, 나머지 칸은 짧게 늦춰 그린다(약 0.1초).
- **카메라 칸**: 지금의 모니터 기능을 그대로 쓴다(판독값, 구도 가이드, 폴스컬러, 녹화 테두리 규칙).
- 3D 칸의 작은 모니터(PiP)는 카메라 칸이 화면에 없을 때만 보인다. **[판단]**
- 휴대폰은 칸 하나만 둔다. 위쪽 시점 메뉴로 3D/탑/카메라를 바꾼다.

### 7-3. 도구 검색 (커맨더)

- ⌘K(Mac) / Ctrl+K(Windows)로 연다. 툴바의 검색 칸을 눌러도 열린다. 화면 가운데에 입력 한 줄과 결과 목록이 뜬다.
- 검색 대상: 팔레트 도구, 인스펙터 섹션(예: "초점" → 카메라 초점 섹션 열기), 내보내기 메뉴 항목, 보기·배치 전환, 샷 동작, 설정(간편/프로, 튜토리얼, 포커스 연습, 조작 가이드)
- 결과는 그룹별(도구 · 설정 · 샷 · 내보내기 · 보기)로 나누고 단축키를 같이 보여 준다.
- 지금 쓸 수 없는 것은 숨긴다(꺼진 버튼, 간편 모드에서 프로 전용, 지금 화면에 없는 기능).
- 빈 입력일 때는 최근 쓴 것 5개와 즐겨찾기를 보여 준다(기기에 저장).
- 실행은 기존 버튼을 누르는 것과 같은 길로 한다. 새 동작을 따로 만들지 않는다.

### 7-4. 휴대폰 작업 공간

```
가로(기본)                                      세로(스토리보드만)
┌ 씬 이름  ↶ ↷  저장 ● 내보내기 ┐            ┌ 씬 이름     ↶ ↷  내보내기 ┐
│ [3D|탑|카메라]                │            │ S01 그림 / 정보 / 글     │
│        단일 뷰포트             │  ┌ 시트 ┐  │ 프롬프트                 │
│                              │  │ 렌즈… │  │ S02 …                  │
├ 카메라 조명 세트 샷 스토리보드 ─┘  └──────┘  └ 편집으로                 ┘
```

- 위: 프로젝트명, 되돌리기·다시, 저장 상태, 내보내기 **[사용자]**
- 가운데: 단일 뷰포트. 시점 메뉴는 뷰포트 왼쪽 위의 작은 전환으로 둔다 **[판단]**
- 아래 탭: 카메라 · 조명 · 세트 · 샷 · 스토리보드 **[판단]**
- 설정 시트:
  - 탭을 누르면 열린다. 단계는 세 가지다: 살짝(주요 값 하나), 반, 전체. 닫을 수 있다.
  - 세로 화면에서는 아래에서 올라오고, 가로 화면에서는 오른쪽에서 나온다. 가로 높이가 390px이라 아래 시트는 화면을 너무 가리기 때문이다. **[판단]**
- 시트 안은 그룹을 하나씩 보여 준다. 예: 카메라 → 렌즈 | 초점 | 노출 | 거리 | 센서 중 하나
- 숫자 값은 누르면 직접 입력한다. 손가락이 닿는 범위는 44px 이상으로 한다.
- 카메라 도구(끌기·수평·A·B 바라보기·맞춤)는 카메라 시트를 "살짝" 열었을 때의 첫 줄에 둔다 **[판단]**
- 컴퓨터 전용(세 화면, 팔레트 전체, 커맨더)은 휴대폰에 두지 않는다.

### 7-5. 스토리보드 작업 칸 **[사용자]**

편집과 따로 있는 작업 칸이다. 컴퓨터는 타임라인 머리에서, 휴대폰은 아래 탭에서 들어간다. 세로로 쓰는 화면이다.

```
┌──────────────────────────────────────────┐
│ S01  [그림 16:9]   풀 샷 · 아이 레벨 · 35mm │
│                    고정 · 3초              │
│      액션 ____________ (쓸 수 있음)        │
│      대사 ____________                    │
│      메모 ____________                    │
│      프롬프트 (기본 | 실사)  [복사]          │
│      "A woman stands …"                  │
├──────────────────────────────────────────┤
│ S02 …                                    │
└──────────────────────────────────────────┘
```

- 샷마다 한 줄씩 위에서 아래로 놓인다.
- 정보: 샷 번호, 샷 크기, 앵글, 렌즈, 무빙, 길이. 자동 판정값(`autoSize`, `autoAngle`, `optics`)을 그대로 쓴다.
- 쓸 수 있는 글: 기존 필드 `action`, `dialogue`, `note`를 그대로 쓴다. 새 저장 필드는 없다.
- 프롬프트: 기존 AI 프롬프트 함수(이미지·영상)로 샷마다 만든다. 문체 전환(기본/실사)과 복사 버튼을 둔다.
- 그림이나 샷 번호를 누르면 편집으로 돌아가 그 샷을 고르고 3D로 연다.
- 순서 바꾸기(끌기), 새 샷을 둔다.
- 휴대폰: 스토리보드에서는 세로 화면을 쓰고 돌려 달라는 안내를 띄우지 않는다. 편집으로 돌아가면 기존 규칙(가로)이 다시 적용된다.
- 인쇄·PDF는 기존 콘티 인쇄를 유지한다. 이 화면은 작업용이다. **[판단]**

## 9. 간편 모드 기능 **[사용자]**

### 9-1. AI 프롬프트 기본값
- 문체 전환을 둔다: **기본** / **실사**. 간편 모드 기본값은 기본, 프로 모드 기본값은 실사다. 고른 값은 기기에 저장한다. **[판단: 프로 기본값]**
- **기본**은 실사 강제 문구("real photograph", "film grain", "not a 3D render", "실사 영상")를 빼고, 구도·카메라·조명·인물 정보만 남긴다. 글자·워터마크 금지 문구는 남긴다. **[판단]**
- 메뉴 이름은 "AI 실사 프롬프트" → "AI 프롬프트"로 바꾼다.

### 9-2. 클릭으로 샷 크기 · 앵글
- 샷 크기 버튼: 와이드 · 풀 · 니 · 미디엄 · 미디엄 클로즈업 · 클로즈업 · 익스트림 클로즈업(`SIZES`의 WS…ECU. EWS는 프로에서만)
- 앵글 버튼: 아이 레벨 · 하이(부감) · 로우(앙각) · 버즈아이 · 웜즈아이 · 더치(켜고 끄기)
- 동작: 지금 초점 대상 인물(`afKey`)을 기준으로 카메라를 놓는다.
  - 크기: `SIZES[k].h`(보이는 높이)와 지금 렌즈 화각으로 거리를 정하고, 카메라를 인물 쪽 방향선 위로 옮긴다.
  - 앵글: 카메라 높이와 틸트를 `autoAngle()`의 경계값 안쪽으로 정한다.
  - 결과는 `autoSize()` / `autoAngle()`로 다시 판정했을 때 누른 값이 나와야 한다(시험 기준).
- 되돌리기가 된다. 지금 값은 버튼이 눌린 상태로 보인다.
- 자리: 컴퓨터는 카메라 인스펙터 맨 위, 휴대폰은 카메라 시트의 "살짝" 단계. 프로 모드는 카메라 인스펙터의 거리 섹션에 같은 버튼을 둔다. **[판단]**

### 9-3. 사진으로 자동 구도
- 진입: "사진으로 구도" 버튼. 휴대폰은 카메라로 바로 찍거나(`<input type="file" accept="image/*" capture="environment">`) 앨범에서 고른다.
- 인식: MediaPipe 자세 인식(Pose Landmarker lite)을 처음 누를 때만 불러온다.
  - 모델과 실행 파일은 저장소에 두고(`vendor/mediapipe/`), 서비스 워커가 캐시한다.
  - 사진은 기기 밖으로 보내지 않는다.
- 사진에서 읽는 것: 사람 1명(가장 큰 사람)
  - 몸의 어디까지 보이는가 → 샷 크기(`SIZE_RULES` 기준)
  - 머리·어깨·엉덩이의 위치 → 화면 속 위치
  - 어깨·코 방향 → 바라보는 방향
  - 상하 원근 → 하이/로우 앵글
- 적용:
  - 초점 대상 인물을 기준으로 지금 샷의 카메라(위치·팬·틸트)를 놓고, 인물의 바라보는 방향을 맞춘다. 렌즈는 바꾸지 않는다.
  - 되돌리기가 된다.
- 비교: 적용 뒤 카메라 화면 위에 사진을 옅게 겹쳐 보여 준다. 겹치기는 켜고 끌 수 있다.
- 사람을 못 찾으면: 사진 위에 머리 꼭대기와 발(또는 보이는 가장 아래)을 눌러 표시하게 하고, 그 두 점으로 계산한다.
- 저장: 사진은 기본으로 저장하지 않는다(화면에만). 계속 겹쳐 보려면 프로젝트에 사진을 넣는 선택 항목 `s.ref`(작게 줄인 JPEG)를 둔다. 공유 링크에는 넣지 않는다. **[판단]**

## 10. 작업 순서 (하위 프로젝트)

각 단계는 따로 계획(writing-plans)을 세우고, 끝나면 시험·사진으로 확인하고 커밋한다. **[판단]**

| 순서 | 작업 | 내용 | 끝났다는 기준 |
|---|---|---|---|
| ① | 기반 | Playwright 시험을 저장소로 옮김(`tests/e2e/`), 실행 명령 하나(`npm test`), 기존 시험 통과 | 저장소만으로 시험이 돈다 |
| ② | 디자인 시스템 | `lens` 테마 되살림(SUIT), 앱 토큰 교체, 버튼·입력·탭·인스펙터 모양 통일 | 모든 화면이 한 벌의 색·글꼴·모서리로 보인다 |
| ③ | PC 작업 공간 | 툴바, 도구 팔레트(그룹·접기·즐겨찾기), 인스펙터(고른 대상별), 타임라인(합침·접기·높이) | 기존 기능이 모두 새 자리에서 작동 |
| ④ | 뷰포트 | 칸 객체, 칸마다 입력, 한 화면/세 화면, 경계 조절, 더블클릭 최대화, 칸별 시점·옵션 | 탑 칸에서 옮긴 인물이 3D·카메라 칸에 바로 보인다 |
| ⑤ | 커맨더 | ⌘K 검색, 최근·즐겨찾기 | 검색으로 모든 도구를 실행 |
| ⑥ | 스토리보드 작업 칸 | 세로 목록, 글·정보·프롬프트, 누르면 편집으로 | 샷을 눌러 그 샷의 3D 편집으로 간다 |
| ⑦ | 모바일 | 위 바, 단일 뷰포트, 아래 탭, 설정 시트(3단계, 가로는 오른쪽), 숫자 입력 | 휴대폰 가로·세로 사진과 시험 통과 |
| ⑧ | 홈 | 프로젝트 관리 중심으로 다시 배치 | 새로 만들기·불러오기·최근·템플릿·튜토리얼·포커스 연습 작동 |
| ⑨ | 간편 모드 | AI 프롬프트 기본, 클릭 샷 크기·앵글, 사진 자동 구도 | 누른 크기·앵글이 다시 판정과 일치, 사진 시험 이미지로 구도 적용 |
| ⑩ | 전체 확인 | 원문 PHASE 7 목록 전부 | 목록 전부 통과 |

순서를 정한 이유:
- ①이 없으면 나머지를 확인할 수 없다.
- ②·③·④는 모든 화면의 바탕이다.
- ⑤는 ③의 도구 목록을 쓴다.
- ⑥·⑦은 ③의 인스펙터 구조를 쓴다.
- ⑨의 계산(크기·앵글·사진 인식)은 언제든 할 수 있지만, 버튼을 놓을 자리가 ③·⑦에서 정해진다.

## 12. 검토 뒤 정한 것 (검토자 질문에 대한 답)

1. **2화면**: 사용자 동의로 뺀다. 저장된 `previo.vp = '2'`는 세 화면 `'3'`으로 읽는다. **[사용자]**
2. **카메라 칸에서 끌기**: 지금처럼 팬·틸트(두 손가락·휠은 달리)다. 카메라 칸에서는 물체를 옮기지 않는다. 물체를 고르고 옮기는 것은 3D·탑 칸에서 한다. "어느 칸에서든 옮기기"는 3D·탑 칸에 적용한다. **[판단]**
3. **스토리보드와 기존 보드**:
   - 새 세로 목록이 화면의 보드 보기를 대신한다. 같은 길(`setView('board')`, `#boardView`, `#board`, `buildBoard()`, B 키, `#boardBtn`)을 쓰고 안의 내용만 바꾼다.
   - 인쇄·PDF는 인쇄용 CSS로 지금의 콘티 칸 배치를 유지한다. **[판단]**
4. **컴퓨터/휴대폰 기준**:
   - 기준은 지금 값(폭 1000px 이상, 높이 560px 이상이면 컴퓨터)을 그대로 쓴다. 7-1의 1024×600은 이 값으로 바꾼다.
   - 세로 태블릿과 세로 휴대폰은 휴대폰 배치(아래 시트)를 세로로 쓴다. 돌려 달라는 안내는 지금처럼 폭 719px 이하 세로 휴대폰의 편집 화면에서만 띄운다. **[판단]**
5. **시험**: 지금 세션 임시 폴더에 그대로 있다(`harness.js`와 시험 파일들). ①은 이것을 저장소로 옮기는 일이다. **[확인함]**
6. **design-team**: 이번 리디자인은 사용자가 Superpowers 방식으로 진행하고 배치·묶음 판단을 맡겼다. 이 문서의 색·버튼·배치가 확정안이다. 단계마다 design-team 회의는 열지 않는다. **[사용자 지시에 따름]**
7. **사진 구도에 사람이 없을 때**:
   - 인물 A는 모든 샷에 늘 있다(`s.A`). 그래서 초점 대상이 없거나 '가운데'(auto)면 A를 기준으로 놓는다.
   - 사진에서 사람을 못 찾으면 9-3의 두 점 표시로 넘어간다. 인물을 자동으로 더하지 않는다. **[판단]**
